Nexora는 plain async while 에이전트 플래너와 중앙 Orchestrator 실행 경계를 결합한다. 모델은 도구 실행을 요청하고, Orchestrator는 정책·순서·멱등성·중단·복구를 소유한다. LangGraph 실행 경로와 도구 실행 후 suspension은 제거됐다.

02 · Tool semantics

요청 기록과 실제 실행을 분리한다

모델의 AIMessage(tool_call=A)는 실행 증거가 아니다. 권한 게이트는 요청과 executor 사이에 있고, 모든 요청은 최종적으로 대응하는 ToolMessage를 가져야 한다.

TOOL REQUEST ≠ TOOL EXECUTION  ·  pre_tool_use → decision → effect

허용 경로

executed
  1. AIMessage(tool_call)모델의 실행 의도 기록
  2. record_pending호출 순서를 effect보다 먼저 커밋
  3. pre_tool_use → Continue정책과 권한을 실행 직전에 판정
  4. running → executor → donecall id로 내구성 있게 실행
  5. post_tool_use + ToolMessage실제 결과를 transcript에 주입

승인 대기

suspended
  1. pre_tool_use → Suspend도구는 아직 실행되지 않음
  2. persist continuationcall, request, snapshot, rules version 저장
  3. AgentSuspendedworker를 종료하고 compute 0으로 대기
  4. signal → on_resume승인을 권한으로 믿지 않고 현재 규칙 재검증
  5. execute or deny허용된 경우에만 effect와 post event 발생

새 요청 전환

cancelled
  1. new HumanMessageinteractive wait 중 새 입력 도착
  2. ToolMessage(code=cancelled)답 없는 tool request를 먼저 닫음
  3. effect step = done(cancelled)늦은 승인이 실행하지 못하게 차단
  4. HumanMessage admit취소 결과 뒤에 새 요청을 원자적으로 정렬
  5. same run resumesrun fork 없이 최신 지시로 전환
!

도구 결과의 type: suspend는 금지된다. 승인은 실행 전 권한 개념이다. 일반 도구가 예약된 결과를 반환하면 InvalidToolResult로 실패하며 완료 effect로 기록되지 않는다. 과거 tool-originated suspension도 권한 승인으로 재해석하지 않고 fail-closed 한다.

03 · Durable recovery

체크포인트가 아니라 effect 원장으로 복구한다

외부 effect 성공과 상태 저장 사이의 장애창은 graph checkpointer도 제거하지 못한다. Nexora는 StepLog, call-id 멱등성, 순서 결정성, lease/fencing을 복구 계약으로 사용한다.

ABSENT→
실행 가능아직 effect intent가 없음
RUNNING→
불확정 구간재조정 또는 같은 idempotency key 필요
DONE→
결과 재사용도구와 모델을 다시 실행하지 않음
WAITING→
worker 없음승인 signal까지 continuation만 존속
장애 시점원장에 보이는 것복구 행동
모델이 호출을 낸 직후pending round + ordered callsrecover_pending이 모델 턴을 재호출하지 않고 호출별 상태를 조회
도구 실행 전effect absent정책을 다시 평가하고 순서대로 실행
도구 실행 도중effect running무작정 재실행하지 않고 Indeterminate; idempotency/reconciliation 필요

×

LangGraph 실행 경로는 ADR-005에서 철회됐다. StepLog와 recover_pending이 양쪽 모두 필요했기 때문에 graph program counter는 두 번째 내구성 추론만 추가했다. 현재 source of truth는 StepLog 하나이며 gate 재평가는 허용하되 완료 effect는 재실행하지 않는다.

04 · Event surface

결정, 신호, 관측을 세 경로로 분리한다

이벤트 subscriber의 반환값으로 실행을 제어하지 않는다. load-bearing 결정은 awaited typed ControlPlane, 외부 답은 durable inbox/signal, EventStream은 발생한 사실의 관측만 담당한다.

Control · awaited

흐름을 바꾸는 결정

호출자가 반환값을 직접 받고 즉시 다음 transition을 선택한다. 각 지점은 서로 다른 reducer 규칙을 가진다.

on_inputs → inputs | Halt입력 mask/rewrite/drop 후 context admission

06planner에는 권한 정책과 별도 checkpointer를 넣지 않는다.

Explicitly not hidden

자동 transcript persistence, 실제 compaction 처리, attachments는 아직 별도 과제다. 현재 crash recovery는 durable transcript를 호출자가 명시적으로 제공한다.

순서가 설계다

Claude Code의 hasPermissionsToUseToolInner 모델. 구독자 답은 입력이고 최종 권한이 아니다 — allow를 받아도 규칙층을 다시 통과해야 한다. 그리고 bypass 진입점이 규칙층 아래에 있는 것이 불변식이다. nexora에는 이 규칙층이 아직 없다.

구현되고 고정된 것

  • 채널 하나 — Emit이 답을 돌려주고, blocking이면 예외가 run을 멈춘다
  • PRE_TOOL_USE 구독 답이 allow / deny / ask
  • Orchestrator — 스텝 메모이제이션 · signal
  • run_agent — done만 값, error·suspended는 올림
  • 순차 배치 · 재개 진입 · 발행자 하나

미구현 · 최우선

권한 해석기가 없다

  • 구독자 답이 최종이다 — hook allow 재검증이 없다
  • 규칙층 1a~1g 전체 · bypass 면역 개념 없음
  • tools.check_permissions() — Protocol 문구만 있고 부르는 곳이 없다
  • 모드 변환층(마지막 적용) · denial 한도
  • 룰 매칭 — 툴 전체 vs 컨텐츠 단위, MCP 정규화

  • StepLog — Postgres · lease 없음 → exactly-once 아님
  • suspend 스냅샷 저장소 → 라운드 중간 재개 불가
  • 턴 내부 압축 · 이미지 블록 주입 · thinking
